## 1. Co je STOPA

Jedna unifikovaná forenzní workbench místo pěti komerčních nástrojů:

| Zdrojový nástroj | Co z něj STOPA přebírá |
|---|---|
| **Magnet AXIOM** | Artifact extraktoři (RE podklad: 237 extraktorů v `docs/re-axiom/`), timeline, case management |
| **Cellebrite UFED / Inseyets** | Mobilní extrakce (FÁZE 6 — zbývá) |
| **X-Ways Forensics** | Disk images: file systems přes TSK, carving, volné bloky (FÁZE 5 ✅) |
| **Belkasoft X** | Registry/plist/SQLite viewers, reporty (reporty = FÁZE 7 — zbývá) |
| **Exterro FTK** | Processing profily, hashing, dedupe, bad extensions, hash sets (FÁZE 1 ✅) |

## 2. Architektura (Clean Architecture)

```
src/stopa/
├── models.py            # Pydantic v2 boundary modely (Case/FileRecord/Artifact/ProcessResult)
├── pipeline.py          # jediný analyze() entrypoint — sdílený CLI i budoucím web GUI
├── cli.py               # argparse: case/add/files/search/timeline/image/stats/profiles
├── domain/              # ČISTÁ logika bez IO → 100% offline testovatelné
│   ├── signatures.py    # magic-byte detekce (PNG/PDF/PE/SQLite/regf/plist/zip…) + zip refinement
│   ├── bad_extension.py # FTK Flag Bad Extensions (s whitelisty, např. ELF bez ext)
│   ├── dedupe.py        # duplicitní mapa podle hashů + statistiky
│   ├── hashing.py       # chunked MD5/SHA-1/SHA-256 v jednom průchodu
│   ├── profiles.py      # 3 profily: forensic / ediscovery / quick (explicitní přepínače)
│   ├── times.py         # forenzní časové konverze: unix, Windows FILETIME, Chrome µs od 1601, Apple CFAbsoluteTime (2001)
│   ├── image_types.py   # detekce typu obrazu (E01/AFF4/RAW-DD + podkladový FS NTFS/FAT/ext/HFS+/MBR)
│   └── carving.py       # carving engine: magic bytes v bufferu + odhady velikosti (PNG/JPEG/PDF)
├── artifacts/           # AXIOM-style extraktoři (IO jen v entrypointech, čistí matchers testovatelní)
│   ├── sqlite_extract.py    # browser history (Chrome/Firefox) + messaging (iMessage/SMS/call logy) + triage DB
│   ├── registry_extract.py  # Windows registry hives (regf/regipy): Run/RunOnce/MountedDevices/User/Environment
│   └── plist_extract.py     # Apple property lists (binární i XML, nativní plistlib) + date artifacty
├── data/                # IO vrstva
│   ├── db.py            # SQLite case DB: cases/sources/files/artifacts + FTS5 external-content index + triggery
│   ├── ingest.py        # walk důkazových zdrojů (symlinks se nesledují — forenzní konzervativita)
│   ├── tsk.py           # The Sleuth Kit CLI wrapper (mmls/fls/icat/blkls/img_stat), STOPA_TSK_BIN, TskError
│   └── image_pipeline.py# disk image pipeline: detekce → partice → soubory → case DB + carving
└── __main__.py          # python -m stopa
```

**Klíčové design rozhodnutí:**
- **Jeden SQLite soubor na případ** (`$STOPA_DB_DIR/case-<id>.db`) — single source of truth, přenosný case.
- **Idempotentní upserty** podle `(source_id, rel_path)` — re-ingest nevytváří duplikáty; artifacts podle `(source_id, artifact_type, rel_path)`.
- **Dispatch mapa `ARTIFACT_EXTRACTORS`** (signatura → extraktor) v pipeline — nový typ souboru = jeden řádek.
- **Čisté matchery + IO wrapper** u každého extraktoru — doménová logika testuje se syntetickými daty bez reálných souborů.
- **Defenzivní programování:** chybějící sloupce/klíče/neplatné časy → přeskočeno bez výjimky; volitelné závislosti (regipy) lazy import + ImportError → `[]`.

## 4. CLI přehled

```bash
stopa case new "Název" --examiner "..."          # nový případ (SQLite DB)
stopa add <case_id> /cesta --profile forensic    # ingest + pipeline [+ --hash-set bad.txt]
stopa files <case_id> [--bad-ext|--dups|--family image]
stopa search <case_id> "dotaz"                   # FTS5: fráze, prefix *, AND/OR/NOT
stopa timeline <case_id> [--type ...] [-v]       # chronologická stopa artifactů
stopa image <case_id> /cesta/ke/obrazu.img       # disk image (TSK) [+ --no-carve]
stopa stats <case_id>                            # statistiky případu
stopa profiles                                   # seznam processing profilů
```

**Profily:** `forensic` (MD5+SHA256, signatury, bad-ext, dedupe, hash sets, artifacts), `ediscovery` (MD5-only, bez artifactů), `quick` (jen SHA-256 + signatury).

## 6. Známe limity / otevřené body (pro revizi)

1. **E01/AFF4** — detekce typu funguje, ale čtení obsahu vyžaduje `libewf`/`afflib` (v TSK buildu nezapojeny; RAW/DD plně funkční).
2. **Carving** — běží na celém bufferu obrazu (chunking pro obrazy > RAM zatím chybí); odhady velikosti jen PNG/JPEG/PDF, ostatní typy = do konce bufferu.
3. **NTFS** — TSK ho umí číst, ale E2E proběhl na FAT16; reálná NTFS partice (`/dev/nvme0n1p2`) není čitelná bez root (zařízení `root:disk 660`).
4. **iMessage** — detekce podle schématu `message`+`handle`; cloud varianta (`CloudAppleIMessageArtifact` z RE mapy) zatím neobsazena.
5. **PII maskování** — STOPA nemaskuje; v E2E FÁZE 4c byly maskovaná čísla už ve fixture DB (LM Studio redakce při generování heredoc).
6. **Web GUI (FÁZE 2)** — pipeline je na něj připravený (`analyze()` bez CLI závislostí), ale UI chybí.
